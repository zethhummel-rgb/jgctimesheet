# JGC Portal Design System

The design system is the shared visual source for new portal pages and for existing sections that are deliberately migrated. It is loaded by `common.js`, so every portal page receives the same tokens and components.

## Compatibility Rule

Do not replace an existing page's table, form, card, or feature CSS simply to adopt the design system. Existing page styles remain intact until that section is tested and intentionally migrated.

All shared design-system classes begin with `jgc-`. Generic names such as `.card`, `.panel`, `.tabs`, `.button`, and `table` must not be added to the shared stylesheet because they can change older pages unexpectedly.

## New Page Shell

```html
<body class="jgc-page">
  <main class="jgc-page-shell">
    <header class="jgc-page-header">
      <div class="jgc-brand"><img src="logo.webp" alt="John Gordon Construction"></div>
      <h1>Page Name</h1>
      <p>Signed in as: Employee Name</p>
    </header>

    <section class="jgc-panel">
      <h2 class="jgc-section-title">Section Name</h2>
    </section>
  </main>
</body>
```

Use `jgc-page-shell--wide` for admin pages or dense reporting views.

## Buttons

```html
<button class="jgc-button" type="button">Save</button>
<button class="jgc-button jgc-button--secondary" type="button">Close</button>
<button class="jgc-button jgc-button--danger" type="button">Cancel</button>
<button class="jgc-button jgc-button--icon" type="button" aria-label="Refresh" title="Refresh">
  <i data-lucide="refresh-cw"></i>
</button>
```

Use icon-only buttons for familiar commands such as close, refresh, download, and delete. Always include `aria-label` and `title`.

## Forms

```html
<div class="jgc-form-grid">
  <div class="jgc-field">
    <label class="jgc-label" for="job">Job</label>
    <select class="jgc-select" id="job"></select>
  </div>
  <div class="jgc-field">
    <label class="jgc-label" for="date">Date</label>
    <input class="jgc-input" id="date" type="date">
  </div>
  <div class="jgc-field jgc-field--full">
    <label class="jgc-label" for="notes">Notes</label>
    <textarea class="jgc-textarea" id="notes"></textarea>
  </div>
</div>
```

## Tables

```html
<div class="jgc-table-wrap">
  <table class="jgc-table">
    <thead>
      <tr><th>Name</th><th>Status</th><th>Actions</th></tr>
    </thead>
    <tbody>
      <tr>
        <td>Example</td>
        <td><span class="jgc-badge jgc-badge--success">Active</span></td>
        <td><div class="jgc-table-actions"></div></td>
      </tr>
    </tbody>
  </table>
</div>
```

Existing tables do not need these classes unless they are being migrated and visually checked on desktop and mobile.

## Tabs And Feedback

Use `jgc-tabs` as the container and `jgc-tab` for each tab. Use `active`, `aria-selected="true"`, or `aria-current="page"` for the selected state.

Feedback components are `jgc-notice`, `jgc-notice--warning`, and `jgc-notice--danger`. Status labels use `jgc-badge` with the success, warning, danger, or info modifier.

## Shared Navigation

The top portal navigation and mobile sticky navigation are generated by `common.js`. Do not duplicate either menu inside a new page.

The mobile sticky navigation keeps Home, Timesheets, PO, WO, and Inspections as quick links, followed by a More button that opens the remaining portal destinations.

The admin navigation is also generated from the single `JGC_ADMIN_NAV_ITEMS` definition in `common.js`. Admin pages may retain their original menu markup as a no-JavaScript fallback, but labels, order, destinations, active state, and accessibility are replaced from the shared definition at runtime.

Pages named `*-admin.html`, plus `admin.html`, `accounts.html`, and `notification-settings.html`, receive the shared admin navigation automatically. A new admin page does not need a copied list of admin buttons.

The shared hook adds `jgc-admin-page-title`, `jgc-admin-user-line`, and `jgc-admin-brand-region` to the existing admin header elements. These are compatibility hooks: feature-specific page layout remains in the page stylesheet. Feature-level tabs are never treated as admin navigation.

## Change Checklist

1. Use an existing `jgc-*` component before creating new styling.
2. Add a new design token instead of copying a colour or spacing value across pages.
3. Keep feature-specific layouts in their feature stylesheet.
4. Check desktop and mobile widths before removing any legacy CSS.
5. Advance the service-worker cache when shared CSS or navigation changes.
